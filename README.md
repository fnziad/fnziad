## How I approach software

```text
operational problem
    → people, workflow, and constraints
    → requirements, scope, and ownership
    → implementation and validation
    → documented delivery and iteration
```

The interesting part is usually not the first version. It is finding where that version fails—unclear ownership, shifting requirements, concurrency, auditability, missing data, or ambiguous state—and rebuilding the plan and system around the real constraint.
